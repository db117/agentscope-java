# AgentScope Java 源码学习计划

目标是能独立追踪一次请求，解释执行过程、状态变化和异常收尾，并能在现有扩展点上完成小改动。学习顺序沿真实场景推进：一次问答 → 工具调用 → 权限与中断 → 会话恢复 → Harness 装配 → 扩展适配 → 服务化。

## 1. 时间与完成标准

默认你熟悉 Java、Maven、JUnit 和基本的 Spring；Reactor 可以边读边补。按 **8 周、每周 4 次、每次 75–90 分钟**安排，合计约 40–48 小时。这里的“第几次”表示学习单元，可以按自己的空闲时间顺延。

前 6 周深入 Core 和 Harness，后 2 周学习代表性适配器与 Service 的端到端路径。完成后应能：

- 从公开 API 跟到模型、工具和最终结果，说明 `call()` 与 `streamEvents()` 的关系。
- 区分 Agent 实例、单次执行、用户、session、turn、run 的身份和状态范围。
- 解释工具许可、人工交互、中断、失败与恢复的处理位置。
- 通过 Middleware、Model、工具或存储接口扩展行为，并用离线测试证明结果。
- 在 Service 中定位认证、产品任务编排、Harness 执行和前端事件消费各自的职责。

整体结构可先参考[项目大纲](项目大纲.md)。每周达到验收标准再往下走；仅浏览完文件不算完成。

## 2. 每次学习的方法

每次只追一个场景，按以下节奏进行：

1. **10 分钟：先读测试。** 找输入、替身模型或工具、断言，写下预期结果。
2. **30 分钟：沿源码跟踪。** 从调用入口进入，只展开当前场景真正执行的分支。
3. **20–30 分钟：做一个实验。** 在已有测试夹具上改变输入、响应或失败时机，运行定向测试观察结果。
4. **15–20 分钟：留下证据。** 记录调用入口、状态变化、事件顺序，以及仍未解释的疑问。

使用 IDEA 的查找调用、查找实现和断点。Reactor 代码同时看“流的组装”和“订阅后的执行”；普通 Java 调用栈可能无法直接串起异步步骤。重点识别 `defer` / `deferContextual`、`flatMap` / `concatMap`、`contextWrite`、`doFinally` 和取消信号。

优先使用测试中的脚本模型和本地夹具。`ReActAgentNewLoopReplyTest` 内的 `ScriptedModel` 可以控制每次模型响应；聊天示例的 `DemoChatModel` 可离线演示工具调用及恢复。真实模型响应的随机性会干扰源码实验。

每周建议保存一篇学习笔记，至少包含：场景与预期、IDEA 源码入口、实际调用顺序、状态读写位置、正常与异常分支、测试命令及实际结果。源码调用流程使用 Mermaid `sequenceDiagram`；每张图后按参与者顺序附“节点 / 源码入口 / 主要职责”表，入口写完整的 `全限定类名#方法()`。没有查实的关系标记为待确认。

### 综合练习

复用现有测试夹具，构造一个离线工具任务：脚本模型提出一次需要确认的工具调用，用户允许后工具执行，随后模型返回最终文本。使用同一身份和持久化后端创建新 Agent 实例，再读取会话。

验收以下行为：

- 确认前工具调用次数为 0，允许后该场景工具调用次数为 1。
- 最终消息与事件流中的结果一致；工具请求与结果能够关联。
- 新实例能恢复预期会话内容，另一用户或另一 session 读不到该内容。
- 在独立分支中制造一次模型失败或中断，说明记录了什么、丢弃了什么、怎样继续。

先用测试表达行为，再决定是否需要改生产代码。若观察到问题，先定位共享实现和所有调用者，再完成最小修复。

## 11. 验证命令与学习记录

以下是学习时运行的命令模板；制定本计划时没有执行这些测试。Java 命令都从仓库根目录运行。

```bash
# 第 1 周第一次：只跑一条离线纯文本用例
mvn -T1C -pl agentscope-core -am test -Dtest=ReActAgentNewLoopReplyTest#textOnlyReplyEmitsExpectedEventOrder -Dsurefire.failIfNoSpecifiedTests=false

# 第 2–4 周：替换为该节列出的目标测试类或方法
mvn -T1C -pl agentscope-core -am test -Dtest=PermissionEngineTest -Dsurefire.failIfNoSpecifiedTests=false

# 第 5–6 周：Harness，连同依赖模块构建
mvn -T1C -pl agentscope-harness -am test -Dtest=AgentSessionTest -Dsurefire.failIfNoSpecifiedTests=false

# 第 7 周：模型扩展的本地解析测试
mvn -T1C -pl agentscope-extensions/agentscope-extensions-model/agentscope-extensions-model-openai -am test -Dtest=OpenAIResponseParserTest -Dsurefire.failIfNoSpecifiedTests=false
```

`-Dsurefire.failIfNoSpecifiedTests=false` 用于让没有匹配测试的上游模块通过。运行后必须检查目标模块的 `target/surefire-reports/` 和汇总，确认目标方法真的执行，记录执行数、失败数和跳过数；仅有 `BUILD SUCCESS` 不足以证明指定用例已运行。

Service 部分按需要在各自目录运行：Go 使用 `make build` / `make test`；前端使用 `npm test` / `npm run lint` / `npm run build`。先核对 README、Makefile 和 package.json 所需环境。前端构建会输出控制台静态资源，实验结束检查工作区差异。

如果做了 Java 源码改动，运行对应模块测试和 `mvn -T1C -pl <module> -am spotless:check`；跨模块或公开契约改动按仓库要求运行 `mvn -B -T1C clean verify`。记录环境阻塞、未执行项和失败原因，保留实际结果。
