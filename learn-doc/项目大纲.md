# AgentScope Java 项目大纲

> 本文按仓库当前目录和 Maven 聚合关系整理，供学习时定位模块。模块清单以各级 `pom.xml` 为准；Service 的 Go 控制面、前端、部署资源和文档不属于根 Maven 聚合构建。

## 1. 项目全貌

AgentScope Java 是用于构建和运行 LLM Agent 的 Java 框架。代码从基础 Agent 能力向上组合为 Harness，再通过扩展对接模型、协议、存储和运行环境；Service 将 Agent 托管为可管理、可观测的服务。

```text
agentscope-core                 Agent 基础运行时与通用 API
       ├── agentscope-harness   工作区、记忆、技能、子 Agent 等工程能力
       ├── agentscope-extensions 可选模型、协议、存储及基础设施适配
       └── agentscope-service   Agent 服务化平台

agentscope-examples             示例应用与功能演示
docs                            面向使用者的文档站点
agentscope-dependencies-bom     第三方依赖版本管理
agentscope-distribution         对外发布的聚合依赖与 BOM
```

上图表达职责层次；具体模块依赖以各模块 POM 为准。

## 2. 仓库顶层模块

根目录 [`pom.xml`](../pom.xml) 聚合以下 Maven 模块：

| 目录 | 作用 |
|---|---|
| `agentscope-core/` | Agent 推理与执行的基础 API、消息、工具、事件和状态能力。 |
| `agentscope-harness/` | 在 Core 上组装面向长任务和生产运行的 Agent 工程能力。 |
| `agentscope-extensions/` | 可选的模型、协议、持久化、渠道及运行环境适配。 |
| `agentscope-service/` | Service 的 Java 公共层、网关、数据面和调度器；同目录还包含独立的 Go 控制面与 React 控制台。 |
| `agentscope-examples/` | 文档示例、Agent 应用和评测示例。 |
| `agentscope-dependencies-bom/` | 集中管理第三方依赖版本。 |
| `agentscope-distribution/` | 发布给使用者的 `agentscope-bom` 与 `agentscope-all`。 |

其他重要入口：[`README_zh.md`](../README_zh.md) 介绍框架和快速开始；[`CONTRIBUTING.md`](../CONTRIBUTING.md) 说明贡献流程；`docs/` 是 Mintlify 文档站点；`learn-doc/` 保存项目学习笔记。

## 3. Core：Agent 基础能力

位置：`agentscope-core/src/main/java/io/agentscope/core/`。它是运行时基础层，主要包按职责可分为：

- **Agent 执行**：`agent/`、`agent/config/`、`agent/user/` 定义 Agent、运行上下文、执行控制、流式执行和用户输入；ReAct 推理循环从这里入手。
- **消息与事件**：`message/` 表示输入和多模态内容；`event/`、`agent/` 中的事件 API 表达执行过程及结果。
- **模型与工具**：`model/`、`model/spi/` 提供模型抽象和扩展接口；`tool/` 包含工具注册、内置工具、文件、代码、MCP 和子 Agent 工具。
- **执行策略**：`middleware/` 扩展执行生命周期；`permission/` 控制工具许可；`interruption/` 支持中断与恢复控制。
- **状态与上下文**：`state/`、`session/`、`memory/` 管理 Agent 状态、会话和记忆；`workspace/`、`skill/`、`rag/` 提供工作区、技能及检索相关抽象。
- **输入输出与诊断**：`formatter/`、`credential/`、`observation/`、`tracing/`、`hook/`、`shutdown/` 和 `util/` 支持格式化、凭据、观测、追踪和生命周期收尾。

建议先读 `agent/`、`message/`、`model/`、`tool/`，再看 `event/`、`middleware/`、`permission/` 与 `state/`。

## 4. Harness：面向任务的组合层

位置：`agentscope-harness/src/main/java/io/agentscope/harness/agent/`。Harness 依赖 Core，把常用的长任务能力组合为更高层的 Agent：

- **入口与装配**：`agent/` 提供 Harness Agent 及配置入口。
- **工作区和文件系统**：`workspace/`、`filesystem/` 管理 Agent 工作区及本地、远端或沙箱文件访问；`artifact/` 管理任务产物。
- **会话和上下文**：`session/`、`memory/`、`memory/compaction/`、`context/` 支持会话、记忆、上下文整理与压缩。
- **委派和协作**：`subagent/`、`team/`、`coordination/`、`bus/` 支持子 Agent、团队协作及事件通信。
- **执行扩展**：`middleware/`、`tool/`、`tools/`、`sandbox/`、`skill/` 提供中间件、工具、沙箱和技能能力。
- **接入与反馈**：`gateway/`、`observation/`、`verification/`、`channel/` 支持渠道接入、执行观测和结果核验。

学习时可从 [`Harness 架构文档`](../docs/v2/zh/docs/harness/architecture.md) 建立概念，再沿各包跟进实现。

## 5. Extensions：可选集成

位置：`agentscope-extensions/`。各适配器按能力拆成独立 Maven 子模块；应用只需依赖实际使用的集成。

| 能力族 | 代表子模块 |
|---|---|
| Spring Boot Starter | 通用 AgentScope Starter，以及 OpenAI、DashScope、Gemini、Anthropic、Ollama、A2A、AG-UI、Nacos、JEV 等 Starter。 |
| 模型 | OpenAI、OpenAI Official、Gemini、Anthropic、DashScope、Ollama；另有模型端到端测试模块。 |
| 协议 | A2A（客户端和服务端）、AG-UI、Chat Completions Web、Agent Protocol。 |
| 状态与存储 | OSS、COS、Redis、MySQL、PostgreSQL、MongoDB、JDBC。 |
| 记忆 | Mem0、百炼 Memory、ReMe。 |
| RAG | Simple、百炼、Dify、RAGFlow、Haystack。 |
| 沙箱 | Kubernetes、AgentRun、Daytona、E2B。 |
| Channel | 公共 Channel 能力，以及钉钉、飞书、GitHub、GitLab、企业微信、微信适配。 |
| 基础设施与治理 | Higress、Nacos（A2A / Prompt / Skill）、技能仓库（Git / MySQL / PostgreSQL）、Studio、JEV / OpenAI Decisions、Scheduler（Quartz / XXL-JOB）、Training、Control Plane 集成。 |

具体子模块列表以 [`agentscope-extensions/pom.xml`](../agentscope-extensions/pom.xml) 及其子聚合 POM 为准。

## 6. Service：Agent 服务化平台

位置：`agentscope-service/`。Service 将 Agent 发布为业务可调用的 Endpoint，并围绕任务执行提供管理、事件、产物和部署能力。

### 6.1 运行组件

| 组件 | 实现位置 | 主要职责 |
|---|---|---|
| Gateway | `service-gateway/`（Java） | 对外入口、认证和 API 路由。 |
| Control Plane | `service-controlplane/`（Go，独立于 Maven 聚合） | 产品资源、发布、Invocation、任务协调及运行时命令；包含 `as` CLI 与 Runtime Host 命令。 |
| Dataplane | `service-dataplane/`（Java） | Managed Harness Runtime、事件日志、SSE、人工交互和工作队列。 |
| Scheduler | `service-scheduler/`（Java） | Channel、定时任务和出站任务调度。 |
| Common | `service-common/`（Java） | Java Service 组件共享的基础代码。 |
| Console | `frontend/`（React） | 管理和观测 Service 的 Web 控制台。 |

### 6.2 配套工程

- `docker/`、`docker-compose.yml`：本地和容器化运行资源。
- `helm/`、`deploy/`：Kubernetes 部署配置。
- `scripts/`、`release/`：开发栈、发布与安装相关脚本和资产。
- `service-controlplane/api/`、`config/`、`internal/`、`sdk/`：Go API、配置、内部实现和 SDK。

Service 的边界、运行模式和开发方式见 [`agentscope-service/README.md`](../agentscope-service/README.md)。

## 7. Examples：可运行示例

位置：`agentscope-examples/`。

- `documentation/`：与框架文档配套的功能示例，如快速开始、工具、结构化输出、MCP、中间件、流式 Web、状态和中断。
- `agents/agentscope-chat/`：支持会话历史和流式交互的聊天应用。
- `agents/agentscope-paw/`：Agent 应用示例。
- `agents/agentscope-dataagent/`：数据分析 Agent 示例。
- `agents/agentscope-codingagent/`：编码 Agent 示例。
- `jev/`：Agent 评测相关示例与基准。

示例聚合入口是 [`agentscope-examples/pom.xml`](../agentscope-examples/pom.xml)；运行说明见 [`agentscope-examples/README.md`](../agentscope-examples/README.md)。

## 8. Docs：用户文档站点

位置：`docs/`，使用 Mintlify 维护。

- `v2/en/`、`v2/zh/`：AgentScope Java v2 的英文和中文文档，覆盖快速开始、Core 构件、Harness、集成、Service、JEV 和博客。
- `v1/en/`、`v1/zh/`：v1 文档。
- `examples/`：文档引用的示例素材；`imgs/`：架构图和页面配图。
- `scripts/`、`package.json`：文档站点校验和开发工具。

学习源码时以源码和 POM 核对具体行为；文档用于理解使用场景和概念边界。

## 9. BOM、发布与仓库工程

- `agentscope-dependencies-bom/`：第三方库版本统一管理，供项目模块使用。
- `agentscope-distribution/agentscope-bom/`：使用者导入的 AgentScope 组件版本清单。
- `agentscope-distribution/agentscope-all/`：聚合依赖，方便一次引入多个组件。
- 根 `pom.xml`：版本、Java 17、构建插件和各 Maven 聚合模块的总入口。
- `.github/workflows/`、`.github/scripts/`：CI 工作流及仓库检查脚本。

## 10. 推荐学习顺序

具体到源码入口、离线测试、实验与验收标准的安排见[源码学习计划](源码学习计划.md)。

1. 从 [`README_zh.md`](../README_zh.md) 和根 `pom.xml` 了解产品目标及模块边界。
2. 在 Core 中依次看 Agent 执行、消息与事件、模型、工具，再看 Middleware、权限、状态和会话。
3. 阅读 Harness 架构文档，然后沿 `HarnessAgent`、工作区、记忆、子 Agent 和沙箱相关包看组合实现。
4. 从 `agentscope-examples/documentation/` 找对应概念的最小示例，再按需要阅读扩展适配器。
5. 学习 Service 时先读 `agentscope-service/README.md` 的组件边界，再分别看 Java 组件、Go 控制面和 React 控制台。

需要追踪具体调用链时，从对应模块的公共入口和测试向实现深入；本大纲只提供模块与职责索引。
